# PWR-002: completed descriptive network experiment

The original schedule is accounted for: 4,250 observations, 9,017 completed jobs and one retained interrupted pairing job. The authorized continuation completed all 4,742 untouched jobs without replacement. Independent review 050 accepted the exact retained data, result/source pins and descriptive interpretation. The earlier administrative failure remains visible, so every statistical claim stays descriptive and the original confirmatory status is withdrawn.

The main practical finding is that a known whole-pairing rejection reference was inexpensive on these sparse degree sequences, while released GlobalCurveball20 gave similar descriptive calibration and detection. We found no pairing power advantage and no demonstrated new-mathematics performance improvement.

## Fixed experiment and results

The primary graph is the complete 39-vertex, 46-link off-diagonal pattern of [NIST BCSPWR01](https://math.nist.gov/MatrixMarket/data/Harwell-Boeing/bcspwr/bcspwr01.html). The separate descriptive case is the complete 49-vertex, 59-link pattern of [BCSPWR02](https://math.nist.gov/MatrixMarket/data/Harwell-Boeing/bcspwr/bcspwr02.html). Labels are matrix indices, not identified real buses. Diagonals were excluded. The null preserves every labeled degree but permits disconnected and physically unrealistic networks.

Before outcomes, we fixed the moderate alternative to retain the first eight edges of the original greedy lexicographic vertex-disjoint matching; the weak alternative retains four. Whole-candidate stub-pairing rejection redraws the residual simple graph. The statistic is overlap with the fixed original graph. Each job uses 49 fresh outputs with distinct frozen recorded seeds; conditional IID assumptions remain unproved. Native chains reset from the observed graph for each output, whereas whole-pairing rejection generates fresh degree-constrained graphs without a chain start. Ties count in the upper tail; reject if at most one output equals or exceeds the observed overlap, giving rank (1+X)/50 and raw cutoff .04. The original 446,132 decimal-string observation/output seeds and all denominators remain unchanged.

Primary recorded job time averages are about .023 seconds for pairing and .038 seconds for Global20 per 49-output batch. These times include reset, sampling, graph validation and record construction, but omit final gzip persistence. They are shared-machine descriptive measurements, not physical-runtime confidence bounds or complete engineering cost. Weak BC39 pairing detected 9/20, rather than demonstrating broadly high sensitivity.

Algorithm choices follow the [official NetworKit randomization tutorial](https://networkit.github.io/dev-docs/notebooks/Randomization.html): ordinary10n/100n, default Global20, preprocessing enabled, and bounded Global10/100 comparisons. Actual native methods use NetworKit 11.2.2. The sufficient ordinary-trade arm uses the published project's unchanged planner/kernel at commit b014f3b8e84954547d4ce464fdad615825a24c3b, with conditional per-output TV 1/4900 and 49-output sum .01. Whole-pairing rejection is an established exact-target method under ideal uniform permutations and constant graph-fiber multiplicities; it is not a newly discovered algorithm. A generic equal-fiber formal lemma does not complete the graph/permutation/finite-PRNG runtime proof.

## Failure, recovery and resources

The original study stopped after 233.680 seconds when its unprotected mmap guard saw an invalid shared ledger; the triggering snapshot was not logged. CPython 3.14.8 clears the `pack_into` destination before packing, and a same-runtime callback demonstrated an intermediate zero. This establishes a concrete possible race mechanism, not a replay proving the unlogged original value. The failed source, compressed truncated EOF, receipts and censored analysis remain unchanged.

A reviewed shared Windows mutex protects all subsequent updates and snapshots. Actual concurrent controls showed no invalid protected reads, invalid unprotected forced-zero reads, and fail-closed abandonment. The original 6,294 complete rows were retained byte for byte. The interrupted `bcspwr01|null|2138|pairing` job remains failed with 61 charged candidates and unknown partial output count/time; its outputs were never regenerated. Its synthetic seconds=0 is an administrative placeholder, not measured zero cost.

Continuation took 255.838 seconds with 116.25 MiB peak working set and zero mutex timeouts. Combined analysis took 43.199 seconds with 151.32 MiB peak. Both exited 0 with clean, known ledgers. Analysis audited 446,083 graphs and 212,451 accepted stub vectors, with zero missing scheduled records and zero unattributed reservations. The merged guard receipt is explicitly derived; both actual process receipts are retained.

Charged cumulative wall is 602.697 seconds before final packaging, including prior timing, failed study, both analyses, repair work and conservative setup reserves. Final packaging charge is separately recorded. Total reservations are 859,938,142 ordinary attempts, 4,935,280 global rounds and 1,232,349 pairing candidates, within the original 1B/5M/10M caps. Runtime: Windows, Python 3.14.8, NetworKit 11.2.2, NumPy 2.5.3, SciPy 1.18.1, psutil 7.2.2. ## Promising directions and limits

1. Small sparse degree-constrained network null tests are a practical benchmark/use case for the established whole-pairing reference. This pilot supports its affordability on these inputs; larger or denser degree sequences may have poor rejection acceptance.
2. Released GlobalCurveball20 is a credible operational baseline here. Its observed R8 response makes an approximate-sampler comparison feasible, but this experiment does not certify its mixing or finite seeded distribution.
3. Explicit conditional trade budgets, retained attempts and failure-aware reporting may improve the auditability of simulation studies. That is a workflow benefit, not evidence that the sufficient trade count improves detection or speed. Completing the concrete runtime law would strengthen the conditional guarantee.
4. Real engineering usefulness still requires a physically justified anomaly mechanism, statistic and null model. Prescribed topology retention alone cannot validate power-grid fault detection. Biological or social-network uses are untested possibilities, not discovered applications of this result.

The published simplex-product dimension-13 optimum is a normalized projection-body volume theorem. It provides no graph runtime, mixing or compression guarantee. This report does not claim exhaustive discovery of applications, upstream adoption, backend certification or engineering improvement. No existing public repository or release was changed by this study.
